# Behavioral Evaluation: 2026-11-06

Scope: the skill revision in this commit, based on `80902fe`. These are synthetic fixtures, not production-site audits or evidence of ranking improvements. The service and social fixtures have no live capture timestamp; the browser fixture was rendered during this evaluation.

## Method

- An independent GPT-6 Luna evaluator received the skill, realistic audit prompts, and the three raw fixtures. It was not given the scoring rubric or intended answers.
- The JavaScript fixture was executed in headless Chrome. Its resulting DOM contained the H1 "Acme plans", the comparison description, and the contact link. The source alone did not contain the rendered page elements.
- Initial results were reviewed against `README.md` in this directory. The same evaluator then reran the scenarios with the updated delivery guidance. This recovery pass was not a new blind evaluation: the evaluator had its prior output.
- No fixture domains were fetched, and no live site, profile, crawler control, or account setting was changed.

## Changes And Recovery

The delivery guidance now says that JavaScript dependence alone does not justify a rendering-architecture change, and that ambiguous domain ownership must be clarified before recommending a primary website. It also requires explicit unknowns for unavailable provenance or measurement fields.

Observed recovery outcomes:

- Services: maintained the conditional live verification before any `noindex` change, and added owner, acceptance, Search Console/analytics sources, and a measurement window.
- JavaScript: classified successful rendering as an observation rather than a defect, recommended no architecture change, and limited the actionable finding to accurate plan/offer information.
- Social-only: requested owner confirmation of domain roles before selecting a primary link; did not audit a guessed domain or treat X 403 as a crawler block.
- All three: disclosed evidence limits and unknown analytics/index/citation state; did not fabricate demand, conversion metrics, or ranking uplift.

Core evidence and recommendation checks passed in recovery. Reporting completeness remained partial: not every finding repeated provenance/time and measurement details, and one coverage limitation still appeared in the findings table despite being labeled unavailable rather than a defect. The final guidance clarifies shared provenance and explicit unknowns. That final wording clarification was reviewed, not followed by another blind evaluation.

## Separate Collector Checks

- All 23 offline/mocked regression tests passed on Python 3.9.6 and Python 3.13.16. Both compile checks passed. Skill frontmatter validation passed with Python 3.13, which has the validator's existing PyYAML dependency; the collector itself needs no third-party packages.
- Independent code review found charset corruption and an incomplete fallback fix. Final rechecking confirmed that unsupported transforms use a warned UTF-8 fallback and preserve the extracted title.
- A live read-only smoke test discovered SVG logo titles overwriting the document title. After the fix, a repeat fetch of `https://developers.google.com/search/docs/appearance/ai-features` returned HTTP 200, its full document title, canonical URL, and headings without truncation or collector errors.
- The same smoke test fetched `https://developers.google.com/robots.txt`, returned HTTP 200, and extracted the declared `https://developers.google.com/sitemap.xml`. It did not crawl the sitemap or infer indexing status.
- The package has no configured GitHub Actions workflows; these are local and direct network checks, not CI evidence.

## Limits

This is a small qualitative forward test. It does not establish consistency across every model, website, browser, or platform. Keep the fixtures/rubric for future material changes; verify a real audit's evidence and delivery contract before treating its findings as ready for implementation. Automated collector regressions and structural skill validation are separate checks.
